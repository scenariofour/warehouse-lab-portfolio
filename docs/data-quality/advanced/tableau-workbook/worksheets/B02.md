## Question and decision

For the selected wave, which reference/size keys explain the discrepancy? A text table exposes exact quantities and identity; a second summary chart would hide the evidence needed for a source-owner question. It supports reconciliation investigation, not identification of failed individual orders.

## Data, formulas and web rebuild

Use [reconciliation.csv](../../public/reconciliation.csv): one union key, primary key reconciliation_id. String dimensions: wave_id, reference_id, size_key, derived Key Presence. Whole-number measures: selected customer units/records, picking units/records, matched, gap and excess. [Shared formulas](../CALCULATION_REFERENCE.md#selected-interpretation-calculations) use record counts for presence, preserving zero-quantity keys.

1. Use the same independent source and parameter logic as B01. Rows: wave_id, reference_id, size_key, Key Presence, each discrete. Retain reconciliation_id on Tooltip/Detail if needed to make identity explicit.
2. Columns: Measure Names. Marks: Text; Measure Values on Text. Retain only selected customer units, picking units, matched units, positive gap units and picking excess units. SUM is valid at unique key marks; never leave unrelated ranks/counts on the card.
3. Tooltip: key, presence and Reconciliation Id, plus gap/excess. Keep units distinct from records. Use full IDs in tooltip when headers truncate.
4. Dashboard actions: B01 and B05 are sources; B02 is target, with String wave_id mapping. Both drills are U2-confirmed. Do not use reference/size/measure fields as accidental extra mappings when the intended drill is the entire wave.
5. For source selectors, copy reconciliation_id into the existing [local lookup](../../../../../scripts/data_quality/lookup_advanced.py). Its authenticated contributing-record ranges do not identify particular failed customer units.

## Error lessons and scope

Reported lessons: Measure Names supplies headers while Measure Values supplies numbers; action source and target are directional. Diagnostic risks: a single combined measure column means Measure Names is missing/misplaced; extra columns mean the Measure Values list/filter is too broad. A table that stays on a wave after another chart changes may have an action filter still active; inspect every incoming action before blaming the parameter.

*My learning summary:* I learned that a detail view needs a declared key and enough fields to explain the number. Showing more rows is not evidence transparency unless I can trace each row and describe what its presence means.
