# Evaluation protocol and observed results

Owner: independent QA/OR reviewer roles unassigned. Author and executor: AI assistant.  
Version: 0.1.0 · 2026-10-17. Status: DRAFT — PENDING HUMAN REVIEW.  
Review requirements: a human reviewer ratifies claims, reference data, thresholds and adequacy for intended use. Automated PASS is an execution result, never a gate approval.

## Contract and execution rules

Each record below contains a claim, scenario, reference, procedure, metric/proposed threshold, actual result, evidence, limitation, reviewer and disposition. `PASS` means the named technical predicate met the proposed threshold; `FAIL` means it did not; `INCONCLUSIVE` means the claim lacks a valid reference or controls. Human review is PENDING for every record. The AI executor is not independent of implementation. [Requirements](REQUIREMENTS.md), [evidence index](EVIDENCE_INDEX.md).

Before running: freeze input/code/config hashes and workload; state whether the purpose is implementation verification, conditional model exploration or operational validation. Never relabel a passing invariant as evidence of field accuracy. After running: retain command output, timestamp, inputs, all outcomes and deviations; compare corrections with the captured baseline. A truncated event log invalidates an event-oracle evaluation. [Evaluation runner](../scripts/evaluate_governance.ts), [scenario runner](../scripts/validate-scenarios.ts).

## References and golden cases

- The publisher manifest and raw bytes are a **golden source snapshot** for provenance, not authoritative confirmation of field semantics.
- The exact source prefix is a pinned regression workload, not a representative or field-labeled benchmark. Its hash and all relevant source hashes are recorded in E-04/E-05.
- Independent BFS is an algorithmic oracle over the declared grid. Synthetic fixtures in [tests](../tests/simulation.test.ts) exercise scarcity, missing SKU and head-on behavior; they are not production input records.
- Independent event/coordinate equations can reveal calculation disagreement. Shared model assumptions remain shared uncertainty and must not be mistaken for external validation.

## Establish missing acceptance thresholds

The owner first specifies a bounded operational decision and the cost of error. A warehouse-domain reviewer must then obtain a reconciled stock snapshot and surveyed layout/floor connectivity, time-stamped observed pick/delivery traces and feasible robot/service constraints. Separate calibration observations from held-out validation windows, pre-register reference definitions and exclusions, quantify measurement uncertainty, and select practical error bounds before comparing outputs. No arbitrary “95% accurate,” improvement percentage or ROI threshold is adopted. [NASA modeling/simulation credibility guidance](https://standards.nasa.gov/sites/default/files/standards/NASA/B/1/NASA-STD-7009B-Final-3-5-2024.pdf) informs this intended-use distinction; no formal conformance assessment is claimed.
