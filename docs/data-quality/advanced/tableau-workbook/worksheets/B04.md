## Question and decision

How much of the full current reconciliation gap is concentrated in the highest-ranked waves? Ranked bars reveal where a small evidence-request batch can begin. Concentration ranks investigation opportunities, not operational damage or confirmed cause.

## Data, formulas and web rebuild

[exception_pareto.csv](../../public/exception_pareto.csv): one positive-gap member within dimension; primary key `(dimension, member_id)`. dimension/member_id are String dimensions; rank is an integer **ordinal**, not an additive measure. gap_units is additive only within one dimension. Cumulative quantity and denominator are repeated/nonadditive values.

1. Filter dimension to `wave`; the published caption confirms this scope. Convert rank to a Dimension and use a discrete pill; place rank on Columns and SUM(gap_units) on Rows, Marks Bar, ordered rank ascending. This is an equivalent rank-header rebuild.
2. Filter rank to 1–20, matching the observed published caption. The earlier planned pTopN/pParetoDimension controls are not claimed as implemented.
3. Tooltip: member_id and `MIN(cumulative_gap_units)/MIN(gap_denominator_units)`, formatted percent. Add individual `SUM(gap_units)/MIN(gap_denominator_units)` if desired; this extra tooltip share is guidance, not confirmed delivery.
4. Include the observed denominator explanation: Top 20=1720 units, full current-gap denominator=13003. Precomputed cumulative values retain full-data ranking after filtering. No action from this sheet was demonstrated.

## The SUM(Rank) lesson

**Reported build error:** SUM(Rank) treated an ordering label as a quantity and collapsed/distorted the intended sequence. Fix: use discrete rank as a grouping header, not SUM(rank). MIN(rank) can display a member's single rank when needed, but summing ranks does not measure concentration. Changing blue/green display alone is not a substitute for choosing the correct role and aggregation.

Fixed denominator is a different issue: do not SUM the repeated 13003 or use a percent-of-visible-total shortcut. The first wave's 168 units are ≈1.29% of all gaps, rather than ≈9.77% of the displayed Top 20. Both arithmetic statements have different populations; only the former answers this sheet's question.

*My learning summary:* I learned to ask what a number represents before accepting Tableau's default SUM. Rank is position; quantity is magnitude; a denominator defines the population of a claim.

## Three self-checks

1. **Why is SUM(Rank) wrong here?** It adds positions instead of preserving the ranked members.
2. **Does Top 20 change the denominator to 1720?** No. The intended share remains against all 13003 positive-gap units.
3. **Can wave and reference Pareto totals be added?** No. They regroup the same gaps and overlap completely in population.
