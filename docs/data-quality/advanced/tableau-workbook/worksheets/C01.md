## Question and decision

Which source size spellings map to which current and literal values, and how much source activity uses each spelling? A text ledger exposes the representation behind a join. It supports asking for a size codebook, not approving a correction because the match count improves.

## Data, formulas and web rebuild

[normalization_tokens.csv](../../public/normalization_tokens.csv): one source/field/exact original token; primary key token_id. source_id/rule_id/original_token/current_value/alternative_value are **String dimensions**, even when they look numeric. token_records/token_units are whole-number measures. This table aggregates original records; one token row is not one source transaction.

1. Connect this CSV. Preserve original spelling and blanks. Create a display-only label:
   `IF ISNULL([original_token]) OR [original_token]="" THEN "[blank source token]" ELSE [original_token] END`.
   Do not coerce missing size into zero.
2. Rows: source_id, rule_id, Original Token Display, current_value, alternative_value, all discrete. Columns: Measure Names. Marks Text with Measure Values on Text.
3. Retain SUM(token_records) and SUM(token_units) only. Do not substitute the generated count of normalization-token rows. The published standalone sheet exposes source/rule filter cards and a Measure Names filter selecting these two measures.
4. Tooltips should preserve the exact original_token, source/rule, record count and units; this is a reconstructable tooltip recommendation, not proof of every stored tooltip field. Use full spellings even if headers truncate.
5. Displayed Dashboard 02 state contains Customer_Order/HALF_SIZE. The origin of that subset is not established; do not assert that C01b selected it. Source/rule filter scope and any action need separate checks.

## Error lessons and scope

Reported lessons: numeric-looking identifiers/tokens may be dimensions; Measure Names/Values must be assigned separate header/value roles. Diagnostic risks: numeric conversion erases raw spelling; extra Measure Values create unwanted columns; COUNT(token_id) counts aggregated token rows rather than the underlying source records. HALF_SIZE comprises ten declared source tokens and sums to 38846 customer records / 67383 requested units in the repository.

Current half-token mapping is an existing inferred normalization. Literal value is an analytical alternative. Neither column means “confirmed before/after correction”; the source is unchanged.

*My learning summary:* I learned to preserve the original representation beside the analytical value. A ledger makes normalization auditable only if I also name the rule, population and approval boundary.
